# Window Arrange

Swift / SwiftUIで作成したmacOS用ウィンドウ配置アプリです。外部アプリ、プラグイン、Swift Packageの外部依存はありません。

## できること

- **ウィンドウ切替**。⌘＋Tabでウィンドウを一覧表示し、最近使った順に切り替え。サムネイル／アプリアイコン、表示条件・並び順・標準タブのまとめ方、テーマと操作キーを設定可能。
- ログイン時の自動起動を設定可能。
- グローバルショートカットの割り当て・変更・解除。左右上下の半分、四隅の¼、画面いっぱい、中央、次のモニター、最小化、フルスクリーン切替に対応。
- 左右・上下の配置を繰り返すモードをラジオボタンで選択。Cycle は同じ画面内で1/2・2/3・1/3を切り替え、Cycle Displays は半分のサイズでディスプレイ間を移動します。
- 名前付きSnapshotの保存、プレビュー、名前変更、削除。
- 複数アプリの位置・サイズ・モニター・最小化状態をまとめて記録・復元。
- **Spacesの所属の記録・復元（実験機能）**。macOS内蔵のシステムAPIをSwiftから直接呼び出します。
- Snapshot保存と選択中のSnapshot復元にもショートカットを割り当て可能。
- メニューバーのみに常駐し、Dockや⌘Tabには表示されません。起動時にメインウィンドウは開かず、ウィンドウを閉じてもショートカットを利用可能。

左右・上下の半分配置は、繰り返しが **None** の場合、macOS 15以降では対象アプリの「Window → 移動とサイズ変更 → 左／右／上／下」をアクセシビリティAPIで実行します。macOSのタイル余白設定も反映されます。標準メニューがない・無効・操作未対応のアプリやmacOS 14では、従来の座標指定にフォールバックします。項目は表示言語に依存しないAX識別子で判別し、識別子が変わった環境でも座標指定を使います。実行後に応答が不明な場合は、標準配置との競合を避けるため座標で上書きせずエラーを表示します。

「画面全体に配置」も、対象アプリの「Window → 画面全体に配置」（Fill）を同じ方式で実行します。繰り返しモードにかかわらず標準機能を優先し、利用できない場合は座標指定にフォールバックします。

Cycle・Cycle Displaysの半分配置と¼などの配置は引き続き座標を設定し、OSのタイル余白設定には連動しません。半分配置と「画面全体に配置」は通常のデスクトップ上で行い、フルスクリーンやSplit Viewには入りません。最小化とフルスクリーン切替はネイティブのウィンドウ属性を操作します。

## ビルド・起動

必要環境：macOS 14以降、Swift 6以降のXcodeまたはCommand Line Tools、Bun。アプリ本体はSwift / SwiftUI、開発ツールはBun上で実行するTypeScriptです。追加のnpmパッケージは不要です。

```sh
bun run build
open "dist/Window Arrange.app"
```

デバッグ版は `bun run build debug`。SwiftPMの追加サンドボックスを起動できないビルド環境では、`WINDOW_ARRANGE_NESTED_SANDBOX=1 bun run build` を使います。

署名の初期設定前はローカル実行向けのad-hoc署名です。開発モードの初期設定後は、通常のビルドでも同じ開発用証明書を自動で再利用します。ほかのMacへの配布ではDeveloper ID署名と公証を別途設定してください。

## 開発モード

Pythonやシェルスクリプト、追加のファイル監視ツールは使用しません。

```sh
bun run dev
```

初回だけプロジェクト専用の自己署名コード署名証明書を作成します。既存の `.local/signing/` がある場合は、その証明書を再利用します。その後、デバッグ版をビルドして `dist/Window Arrange.app` を起動します。

監視には[Bun標準の `--watch`](https://bun.com/docs/runtime/watch-mode)を使用します。Swift・リソースファイルをテキストとしてimportし、`Sources/`・`Resources/`・`scripts/`・`Package.swift`・`package.json` の変更時に開発用ワーカーを再実行します。ファイル追加・削除・名前変更では、Bunの `node:fs.watch` でimport一覧を更新します。ポーリングは行いません。

保存が約0.7秒落ち着いたところで差分ビルドし、署名・検証に成功した場合にアプリを終了・更新・再起動します。ビルドはwatch対象のワーカーとは別の親プロセスが管理します。ビルド中に追加変更があると古いビルドを中断し、後処理が終わってから最新版でやり直します。コンパイルや署名に失敗した場合は、起動中のアプリをそのまま残して次の保存時に再試行します。ビルド済みアプリの差し替え中は、その更新が完了してから次のビルドに進みます。開発ツール自体のロジックを変更した場合は `bun run dev` を起動し直してください。

開発モードではメインウィンドウが自動で開き、直前の表示セクションとウィンドウ位置・サイズを引き継ぎます。終了はターミナルで `Ctrl+C`。監視を終了してもアプリは引き続き利用できます。更新時に終了するのはこのプロジェクトの `dist/Window Arrange.app` だけです。同じアプリを別の場所から起動している場合は、そのアプリを終了してから開発モードを使ってください。

**初回に署名方式を切り替えたときは、アクセシビリティの許可を一度更新してください。** 設定画面でオンでも認識されない場合は、既存のWindow Arrangeの登録を削除して `dist/Window Arrange.app` を追加し直します。その後は同じ証明書・アプリID・配置先を使い続け、再ビルドによる許可の再設定を減らします。証明書や配置先の変更、macOS側での権限取り消しなどでは再許可が必要になる場合があります。開発モードが権限を自動付与することはありません。

証明書と秘密鍵はプロジェクト内の `.local/signing/development.keychain-db`、解除用パスワードは同じディレクトリ内の `password` に保存します。このディレクトリは所有ユーザーだけがアクセスでき、Gitからも除外しています。証明書の信頼設定やシステム全体の設定は変更しません。秘密鍵はインポート時に `/usr/bin/codesign` からの利用を許可します。**`.local/signing/` はビルドキャッシュと一緒に削除しないでください。** 消して作り直すと署名が変わり、再許可が必要になります。初期設定が途中で失敗した場合は同じコマンドで再試行できますが、証明書のインポート前に停止した場合は、案内に従い `.local/signing/` の状態を確認してください。既存の証明書は自動で作り直しません。

```sh
bun run dev:setup          # 署名の初期設定だけ行う
bun run dev:once           # 1回ビルド・更新・再起動する
bun run dev:once --no-open # 1回更新する（起動中なら終了し、再起動しない）
```

既存のApple Development等の証明書を使う場合は、`WINDOW_ARRANGE_SIGNING_IDENTITY` に証明書名またはSHA-1識別子を指定できます。必要に応じて `WINDOW_ARRANGE_SIGNING_KEYCHAIN` も指定してください。この場合は通常のビルドにも同じ環境変数を設定します。開発モードではad-hoc署名へのフォールバックを禁止しています。

SwiftPMの追加サンドボックスを起動できない環境では、`WINDOW_ARRANGE_NESTED_SANDBOX=1 bun run dev` を使います。macOSのディレクトリ監視やキーチェーンへのアクセスが制限される実行環境では、通常のターミナルから実行してください。

## 使い方

1. メニューバーのアイコン →「Window Arrangeを開く」で画面を開きます。初回は画面内の「設定を開く」から、システム設定 → プライバシーとセキュリティ → アクセシビリティでWindow Arrangeを許可します。
2. アプリのウィンドウを好きな場所・大きさ・Spaceに配置します。
3. 「Snapshotを保存」を押します。名前変更・削除はSnapshotの右クリックメニューから行えます。
4. 配置を変更し、保存したSnapshotを選択して「復元」を押します。
5. 「ショートカット」でキーを設定すると、対象アプリを前面にしたまま操作できます。⌘または⌃を含む組み合わせを入力してください。

ショートカット一覧の「変更したショートカットのみ表示」をオンにすると、キーを割り当てた項目だけ表示します。割り当てを解除した項目は対象外になり、チェックを外すと全項目に戻ります。フィルターの選択は次回起動時も維持されます。

終了するには、メニューバーのアイコン →「終了」を選びます。

Spacesの所属を記録しない場合は「設定」のトグルをオフにします。設定は新規Snapshotに適用され、既存Snapshotは保存時の方式で復元します。起動時にはショートカットが未設定です。macOSや他アプリと競合する組み合わせは登録エラーを表示します。キーは物理キーコードで記録するため、キーボード配列変更後は表示と実際のキーが異なる場合があります。

## ウィンドウ切替

初期状態では **⌘＋Tab** で一覧を開き、Tabまたは→で次へ、Shift＋Tabまたは←で前へ移動します。↑・↓では同じ列の上下の行へ移動します。上下端では反対側の行へ回り、最終行の同じ列にウィンドウがなければその行の末尾を選びます。1行だけの場合、↑・↓では選択を変更しません。⌘を押したままでも矢印キーを使えます。矢印キーに個別の操作を割り当てている場合は、その設定を優先します。⌘を離すと選択したウィンドウへ切り替えます。Shift＋⌘＋Tabで逆順に開始できます。Enterで決定、Escでキャンセルできます。クリックでも切り替えられます。保存済みの呼び出しキーは維持されるため、変更する場合は「ウィンドウ切替」のショートカット設定を使ってください。

コントロールセンターと通知センター（デスクトップのウィジェットを含む）は、切り替え対象から自動的に除外します。

表示中のSpaceでは、Chromeのアドレスバーの検索候補など、通常ウィンドウとして取得できないタイトルなしの補助画面も除外します。通常のウィンドウやダイアログ、別Spaceのウィンドウは引き続き切り替え対象になります。

「ウィンドウ切替」→「表示」→「切替画面のサイズ」のスライダーで、切替画面とサムネイルの大きさを70〜150%に調整できます。「標準」で100%に戻せます。設定は次回起動時も維持され、画面に収まらない場合は自動でサイズを抑えます。

⌘＋Tabの呼び出しとキー記録では、macOS標準のアプリ切替との競合を非公開システムAPIで一時的に解除します。キー変更・機能オフ・通常終了時には元の割り当てを復元します。強制終了などで復元できなかった場合は、Window Arrangeの次回起動時に復元します。

「ウィンドウ切替」の設定で、キーを離しても一覧を開いたままにする動作に変更できます。呼び出しキーと、一覧内の次へ・前へ・決定・キャンセルのキーは個別に変更できます。呼び出しにはOption・Command・Controlのいずれかを含むキーを指定します。配置操作と競合するキーは登録できません。他アプリやmacOSとの登録競合は設定画面に表示します。

設定画面の右側には、実際のアプリ・ウィンドウを使ったプレビューを表示します。表示対象・並び順・まとめ方・表示形式・テーマの変更をすぐに反映し、対象の件数や最小化・非表示・Spaceの情報を確認できます。プレビューからウィンドウが切り替わることはありません。「現在のアプリ」は設定操作前のアプリを基準とし、カーソル下の対象は設定画面を開いた時点のものを使います。アクセシビリティが未許可の場合は案内を表示し、画面収録が未許可の場合はアイコンで表示します。

プレビューの各ウィンドウ右上の **−ボタン** で、そのアプリのすべてのウィンドウを切替対象から除外できます。「除外アプリ」には除外したアプリが表示され、各行の「解除」ですぐに対象へ戻せます。除外はすべての表示条件に適用され、後から開いたウィンドウも対象です。設定は保存され、アプリの再起動後も維持されます。

設定できる内容：

- アプリ：全アプリ、現在のアプリ、現在以外、カーソル下のウィンドウ、カーソル下のアプリ。
- Spaces：すべて、表示中、表示されていないSpaces。全Spacesに所属するウィンドウは、表示中の所属Spaceとの交差で判定します。所属不明のウィンドウはSpacesによる絞り込みから除外します。
- ディスプレイ：すべて、切替画面と同じ画面。切替画面は使用中のウィンドウの画面を優先し、取得できない場合はマウスのある画面に表示します。
- 最小化・非表示のウィンドウとウィンドウのない起動中アプリ：表示、非表示、末尾に表示。フルスクリーンは表示・非表示を選択できます。
- 並び順：最近使った順、最近作成した順、アプリ名・タイトルの名前順、Space順。
- まとめ方：アプリごとに1件、各ウィンドウを個別表示。対応するmacOS標準タブのまとめ／個別表示。
- 外観：サムネイル、アプリアイコン。ライト、ダーク、システムに追従。

履歴は起動中のメモリ上で管理します。起動前の使用履歴・作成時刻は復元できず、起動時のウィンドウ順などを初期値とします。ウィンドウIDにPID・起動時刻を組み合わせ、アプリ再起動後に古い参照を再利用しません。AXObserverとアプリ・Spaceの変更通知を使い、API問い合わせと画像取得を一覧のキー処理から分離しています。開いている一覧では選択先をIDで保持し、新規作成・終了で別のウィンドウへ誤ってずれないようにします。

サムネイルはAppleのScreenCaptureKitで一覧を開いたときに取得します。**画面収録の許可は設定画面のボタンから明示的に要求します。** 未許可でもアイコンで切替を利用でき、取得した画像はファイルやSnapshotに保存しません。最小化・非表示・DRMなどで画像を取得できない場合、または選択されていないタブはアイコンを表示します。OSから再起動を求められた場合はアプリを起動し直してください。

最小化・非表示の対象は、選択したときに復帰させます。別Spaceへの切替では対象ウィンドウを移動せず、そのSpaceの表示とフォーカスを切り替えます。Spacesとフルスクリーンの連携は既存機能と同様に非公開システムAPIに依存します。アプリやOSがAXウィンドウ参照を公開しない場合や操作を拒否した場合は切替に失敗することがあり、その理由を表示します。タブはアプリが標準のAXTabGroupを公開する場合に対応し、ブラウザー内部の任意のタブを列挙する機能ではありません。

一覧から閉じる・最小化・終了などを実行する操作、検索、複数の呼び出しショートカット枠、ジェスチャー、CLIによる切替は追加していません。

「設定 → 起動」でログイン時の自動起動を変更できます。macOSのSMAppServiceを使い、実際の登録状態を表示します。システム側で許可待ちの場合はログイン項目の設定へのボタンを表示します。自動起動の設定はアプリバンドルをビルドして起動した状態で行ってください。

## サイズの繰り返し

「ショートカット」または「設定」で、共通のラジオボタンから選びます。選択は保存され、次回起動時も維持されます。既存の保存データでは None が選択されます。

- **None（デフォルト）**：macOS標準の「移動とサイズ変更」で左右・上下を1/2に配置します。標準機能が使えない場合は座標指定を使います。
- **Cycle 1/2, 2/3, and 1/3**：同じ配置ショートカットを押すたび、現在のディスプレイ内で1/2 → 2/3 → 1/3 → 1/2…と切り替えます。
- **Cycle Displays**：サイズは1/2のまま、半画面ずつ巡回します。右半分のコマンドでは「画面Aの右 → 画面Bの左 → 画面Bの右 → 画面Aの左 → …」、左半分では逆方向へ進みます。上下もそれぞれの方向に巡回します。接続中の全ディスプレイが対象で、開いているMacBookの内蔵画面も含みます。1画面の場合は半分の配置を維持します。

対象は左・右・上・下の4操作です。Cycle では左右は幅、上下は高さを切り替え、指定した辺に揃えます。Cycle Displays の画面順は左右の操作では横方向、上下の操作では縦方向の画面配置から決めます。四隅の¼などは従来の動作です。現在の位置・サイズから次の段階を判定するため、Cycle ですでに同じ辺の1/2なら次は2/3になります。手動で別の位置・サイズに変更した場合は1/2から始まります。アプリの最小サイズによって1/3にできない場合は、配置結果にエラーを表示します。

以前の rotation 設定は Cycle Displays に引き継ぎます。Raycast の実機比較で、1/2 → 2/3 → 1/3 のサイズ循環と、内蔵画面・外部画面の左右の半画面を巡る順序を確認しました。

## Spacesの対応範囲

Spaces連携には公開APIがないため、`NativeSpaces.swift` だけに非公開APIを隔離しています。外部のヘルパーアプリ、デーモン、Dockへの注入、SIP設定変更は行いません。

- `dlopen` / `dlsym` でSkyLightとApplicationServicesのシンボルを取得します。
- 通常のSpaceをUUIDで保存し、復元時に現在のUUIDと照合します。デスクトップ番号を固定IDとして扱いません。
- 新しいOSのbridged window management operationを優先し、存在しない環境では従来のSpace移動APIを使用します。
- Space移動の結果を最大2秒待って照合し、拒否や未対応を復元結果に表示します。シンボルの検出は実際の移動成功を保証しません。
- 削除したSpaceの再作成、Spaceそのものの並べ替え、Spaceのモニター間移動は対象外です。
- フルスクリーン／Split View、すべてのデスクトップに表示するウィンドウ、所属が取得できないウィンドウはSnapshotの対象外です。
- Spacesを含むSnapshotの保存時は、接続中のモニターの通常デスクトップを一時的に順番に表示し、ウィンドウを取得してから元のデスクトップへ戻します。MacBookを閉じて外部モニターだけを使う場合も、同じモニターのデスクトップ2以降を対象にします。Space表示や取得に失敗した場合は保存せずエラーを表示します。表示してもアクセシビリティAPIに列挙されないウィンドウの完全性は保証できません。
- macOSの更新で非公開APIの構造・動作が変わる可能性があります。Mac App Store向けには、この機能を除いた構成にする必要があります。

## 復元のルール

ウィンドウの照合は、同一プロセス起動中のウィンドウID、アプリ内で一意のアクセシビリティ識別子、一意の書類URL、一意のタイトルの順です。Macやアプリの再起動後には、古いウィンドウIDを使いません。

VS Code / VS Code Insidersでは、標準のmacOSタイトル形式からプロジェクト名・プロファイル名も照合します。開いているファイルが変わった場合や、保存時の `sample-project — Work` が再起動後に `Welcome — sample-project — Work` となった場合も、既存Snapshotのタイトルから照合できます。Snapshotの作り直しは不要です。独自のタイトル形式・区切り文字への変更や、同じプロジェクト・プロファイルの複数ウィンドウは特定できない場合があります。

候補の一意性は、照合済みのものも含めた全ウィンドウで確認します。列挙順や現在の位置で割り当てを推測しません。保存側・現在側ともそのアプリのウィンドウが1件なら単一ウィンドウとして照合し、複数ウィンドウが曖昧な場合はスキップします。

閉じたアプリ・書類・ブラウザータブは開き直しません。前後関係、アプリの非表示状態、Stage Managerのグループ、フォーカスは記録しません。アプリが独自に設定している「特定のデスクトップに割り当てる」設定の変更にも対応しません。

モニターや作業領域が同じなら保存座標をそのまま使い、解像度・Dock配置・接続モニターが変わった場合は利用可能な領域に合わせて調整します。Spacesを含むSnapshotでは、保存先Spaceが存在しないウィンドウは移動せず結果に表示します。アプリ独自の最小サイズなどで要求した配置にならない場合も、成功件数に含めません。

別のモニターから復元する場合は、まずウィンドウを保存先モニターの座標へ移動して画面移動の完了を待ち、その後で保存先のSpaceと最終座標を適用します。Spaceを先に指定するとモニターをまたぐ復帰が拒否されるケースに対応しています。モニター・Space・位置・サイズが複数回連続して一致するまで成功扱いにしません。

VS Codeなどが非表示Spaceのウィンドウを`AXWindows`から除外しても、保存時や列挙時の参照を保持して復元対象に残します。参照はWindowServerで同じアプリの起動セッションとウィンドウIDが存在する間だけ保持し、終了・再起動後の古い参照は使いません。

アプリを開き直した直後など参照がない場合は、WindowServer側のウィンドウ情報も照合します。対応するmacOSでは対象のSpaceだけを一時表示してウィンドウ参照を取得し、表示していたデスクトップへ戻してから配置を復元します。この取得中は画面が一時的に切り替わります。Space表示APIが未対応の場合や参照を取得できない場合は理由を表示します。

## 保存データ

`~/Library/Application Support/WindowArrange/state.json` にJSONをatomic writeで保存します。ウィンドウタイトルと、取得可能な場合は書類URLを含むため、書類名やファイルパスが保存データに含まれます。画像・書類内容・通信・クラウド保存はありません。書類URLを持たない以前のSnapshotも引き続き読み込めます。

既存ファイルが壊れている場合は上書きを止め、パスとエラーを表示します。ファイルを退避・修復してから再起動してください。

## 検証

```sh
bun run test
"dist/Window Arrange.app/Contents/MacOS/WindowArrange" --diagnostics
"dist/Window Arrange.app/Contents/MacOS/WindowArrange" --restore-diagnostics
```

Swift Testingで座標変換、モニター選択、ウィンドウ照合、JSONの保存・読み込み、破損データ、キー競合判定を確認します。Bun標準のテストランナーで開発モードの失敗・中断時のアプリ維持、署名検証と更新の順序、二重起動防止、Swiftファイルの編集・追加・削除による実際の `bun --watch` 再実行を確認します。開発ツールのテストだけなら `bun run test:tools` を実行できます。`--diagnostics` は権限やSpaceシンボルの検出状況を読み取り、ウィンドウ操作や保存はしません。

`--restore-diagnostics` は、既存Snapshotと現在のウィンドウを照合し、アプリごとの保存数・現在数・照合数と、見つからないSpaceの数を表示します。WindowServerにだけ現れる非表示Spaceのウィンドウ数と、それを含めた照合数も表示します。Spaceの表示切り替え・ウィンドウの移動・設定保存は行いません。

デバッグ版には、自分自身が生成する使い捨てのウィンドウだけを操作する統合チェックも含めています。実行にはアクセシビリティ権限と、Spaces間の検証用に既存の通常デスクトップ2つが必要です。権限は自動的に付与しません。

```sh
bun run build debug
"dist/Window Arrange.app/Contents/MacOS/WindowArrange" --integration-check
"dist/Window Arrange.app/Contents/MacOS/WindowArrange" --native-tiling-check
"dist/Window Arrange.app/Contents/MacOS/WindowArrange" --switcher-check
"dist/Window Arrange.app/Contents/MacOS/WindowArrange" --switcher-preview
```

`--native-tiling-check` はmacOS 15以降で、標準Windowメニューを持つ検証ウィンドウの4方向配置と「画面全体に配置」・ネイティブのタイル状態・アニメーション後の座標維持と、Windowメニューがない場合のフォールバック、Cycleの1/2→2/3を確認します。「画面全体に配置」はCycle・Cycle Displaysでも標準機能を使い、フルスクリーンに入らないことも確認します。このチェックはSpaceを切り替えず、操作するのは自分で生成する使い捨てのウィンドウだけです。

この開発環境での確認結果：Swiftの自動テスト62件・Bunのテスト13件成功。macOS 27.0.1で標準の4方向配置・タイル状態・フォールバック・Cycleの統合チェックも成功しました。ほかのOSバージョン・アプリでの標準メニュー対応は別途確認が必要です。

検証ウィンドウで、AXWindowsから対象が消える状態を模擬し、キャッシュで対象を維持する場合と、空のキャッシュからSpaceを一時表示して再取得する場合の両方を確認しました。実際のVS Codeでも、WindowServerには存在するがAXWindowsには現れない1枚を再取得し、既存SnapshotのMacBook側のSpace・位置・サイズへ復元できることを確認済みです。

検証ウィンドウで、外部モニターのデスクトップ2からMacBookへの復元、逆方向の復元、外部モニター内のデスクトップ2→1、最小化と解除も確認済みです。画面上ではキーの記録・解除と重複キーのエラー表示も確認しました。ほかのOSバージョン・各アプリでのSpaces対応は別途確認が必要です。

実機では、異なるアプリでのショートカット、同一アプリの複数ウィンドウ、異なるSpacesへの移動、モニター着脱、サイズ制約のあるアプリ、削除されたSpaceについて確認してください。
